# S4: D3 Pro platform spike on the emulator

Spike S4 of phase P0 of the Android port of moyun-pos (pili-pos) to the Sunmi D3 Pro, run after P0 on the Android Studio AVD `sunmi_d3_pro_api33` instead of hardware (plan `~/.claude/plans/i-d-like-you-to-vast-koala.md`, section P0, bullet "S4 D3 Pro on the emulator"; DECISIONS.md Q1).

- **Base:** `android/int` at `0b68587` (`docs(android): P0 exit report, phase cards and decisions`). main is not touched in this run.
- **Output merged:** only `docs/android/spikes/S4.md` and the PENDING-S4 updates of `docs/android/DECISIONS.md`, both written by card S4-T8 and cherry-picked onto `android/int`. **Spike code is never merged.** It stays on the task branches and is tagged locally as `android/s4-spike`.
- **Extra scope asked by the user:** evaluate `DevicePolicyManager.getWifiMacAddress` (device owner) as a deviceId candidate; replace the 24 h survival test with a 30 minute soak and document it.
- **One emulator at a time.** Device-owner state is global to the AVD, so every emulator card runs alone in its wave. The only parallel lane is the host-only Rust probe (S4-T2).

## Planner decisions for this run

S4-T8 records the ones that bind later phases under "Decided while the user was away (review)" in DECISIONS.md.

- **PD1 Emulator only.** S4 runs on `sunmi_d3_pro_api33`. What the emulator cannot prove is listed as hardware residue (real Sunmi serial, SUNMI kiosk extension, recovery key combination, USB OTG, bcrypt on the Qualcomm CPU, real Epson, B1c on the real image, real MAC behaviour, Sunmi system OTA).
- **PD2 30 minute soak.** The 24 h survival test is not run in S4 (user request). S4-T7 runs 30 minutes with screen off/on, forced doze and memory trim; the script supports `SOAK_MINUTES=1440` and the 24 h run moves to the P7 D3 Pro runbook (the plan's P7 already lists a 24 h soak).
- **PD3 Spike identity.** Application id `dev.nuagemagique.pilipos.spike` (never the real id `dev.nuagemagique.pilipos`), debug build, signed with the default debug keystore `~/.android/debug.keystore` so every card updates the device-owner app in place. The wrong-key test uses a throwaway RSA key under the worktree's `target/`, deleted at the end. No release key.
- **PD4 deviceId decision rule** (applied by S4-T8 to the measured facts):
  1. `Build.getSerial()` works for the device owner on API 33 and is stable across reboot: the hardware serial stays the deviceId (Q4 stands); the Wi-Fi MAC is recorded as evaluated and not chosen, with the measured reasons.
  2. `getSerial` fails for the device owner, but `getWifiMacAddress` returns a stable value that is not null and not `02:00:00:00:00:00`, also with Wi-Fi off: deviceId becomes the factory Wi-Fi MAC in the Linux format (lowercase, colon separated), FAQ Q505 a).
  3. Both fail: deviceId stays OPEN for the user and the real-device check; P4.4 does not implement the deviceId source until it is settled.
- **PD5 No factory reset is ever triggered**, even on the emulator. `DISALLOW_FACTORY_RESET` is verified from the restriction list and the Settings screen. The AVD may be restarted with `-wipe-data` only by S4-T6, only as the last resort when adb does not come back after the adb-off test.
- **PD6 Clean hand-over to P4.** S4-T7 ends with no device owner, the spike app uninstalled and only user 0. The time zone stays Europe/Brussels.
- **PD7 Evidence.** Each card writes `spikes/s4/notes/<card>.md` and `spikes/s4/evidence/<card>/` (text logs, at most 12 PNG screenshots under 500 KB each). S4.md cites them through the local tag `android/s4-spike`.

## Emulator protocol

- AVD `sunmi_d3_pro_api33`: 1920x1080 landscape, 160 dpi, 4 GB, API 33 arm64 google_apis, no Play, 2 GB SD card. No snapshot exists, so boots are cold boots and the data partition persists.
- `spikes/s4/emu.sh up` (written by S4-T1): reuse a running emulator only if `adb -s <serial> emu avd name` is `sunmi_d3_pro_api33`; if another AVD runs, never kill it, poll for up to 30 min, then report BLOCKED; else start `$ANDROID_HOME/emulator/emulator -avd sunmi_d3_pro_api33 -no-window -no-audio -no-snapshot-save &`, `adb wait-for-device`, poll `sys.boot_completed`, write `$WT/target/s4/emu.mine`. `emu.sh down` stops only an emulator recorded in `emu.mine`.
- Host mocks at `10.0.2.2`: `pos-printer-mock` on 9100 (jobs and control on HTTP 9180; 9101/9181 when taken). Stop what you start.

## Rules (reviewer checks on every card)

- Allowed paths per card. Linux build inputs untouched: `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `src-tauri/`, `ui/`, `crates/`, `deploy/`, `.github/`, `scripts/`. No file under `docs/` except in S4-T8.

- No build outputs, keys or secrets committed (`.so .dylib .apk .aab .aar .dex .a .rlib .jks .keystore .p12 .pfx .pem .key`, `.env*`, `local.properties`, `build/`). Only `gradle-wrapper.jar` and small evidence PNGs as binaries.
- No live module2/HubRise/production calls, no push, no GitHub Actions, no `declare.sh`, no release key, nothing sent to the SPF.
- No em-dash anywhere. Conventional Commits, merge commits included.
- Results measured, never invented; a step that does not finish is NOT RUN with reason and rerun command; no more than 30 minutes looping on one failing probe.
- Run scripts `spikes/s4/run_tN.sh`: start with `emu.sh up`, end with `emu.sh down`, build unless `S4_SKIP_BUILD=1`, write evidence to `${S4_EVIDENCE_DIR:-$WT/spikes/s4/evidence/<card>}` and tee their output to `run.log` there, print `ITEM | VERDICT | detail` lines, exit 1 when a must-PASS item fails, and are idempotent against the AVD state the previous card leaves. Reviewers rerun with `S4_EVIDENCE_DIR=$WT/target/s4/review/<card>` so committed evidence stays untouched.
