# P2: pos-ffi facade + JVM tests

Phase P2 of the Android port of moyun-pos (pili-pos) to the Sunmi D3 Pro (plan `~/.claude/plans/i-d-like-you-to-vast-koala.md`, section "P2: pos-ffi facade + JVM tests", the invariants and the orchestration protocol). A separate Cargo workspace `android/rust` builds `pos-ffi` (`libpos_ffi.so` / host `libpos_ffi.dylib`), a UniFFI facade that mirrors the 84 cert Tauri commands 1:1 over the frozen `crates/pos-engine`, plus a minimal Gradle build whose `:pos-core` module runs JUnit tests against the host dylib and the host mocks.

- **Base:** `android/int` at `175d3efe9003d8a4bbd35ec97267d7ea32c074d4` (`docs(android): P1b phase cards, exit report and exit decisions`). main (`96728e1`) and `cert/v1.0` (`d6210ca`) are not touched. Nothing is pushed.
- **Rule of the phase:** P2 adds files under `android/`, `scripts/android/` and `docs/android/` only (never `docs/android/baseline/`). No Linux build input changes: the soft freeze tag does not exist (PD47), so `042d91135940cb3f678a3f5e2947744a9d05ce4d` is the provisional freeze point (PD48) and every card and the phase gate run `check_linux_frozen.sh --ref 042d911...`.
- **Inputs read by the planner:** the plan, `docs/android/phases/P1b-exit.md`, `docs/android/DECISIONS.md` (sections 2, 4, 5, 9, 11 and PD1 to PD50), `docs/android/ENGINE.md`, `docs/android/spikes/S2.md` and S3.md, the code at `175d3ef`, moyun-handheld's Gradle conventions.
- **Measured starting point (175d3ef):** 86 Tauri wrappers, 84 in the cert build (`issue_b2b_invoice`, `sign_invoice_fiscal` are peppol only), all single calls (`check_ipc_wrappers.py --map`); error registry `errors::ALL` 63 codes + `errors::hubrise::ALL` 22 codes = 85 (plus the FDM-path code `FDM_ANSWER_PENDING`); two wrappers return `serde_json::Value` (`check_fdm_status`, `list_fiscal_events`); no `android/` directory; no `linux-*` tag; disk 34 GB free, `int/target` 27 GB; Rust ws inventory 1479 tests (floor 1355).

## Planner decisions (decided while the user was away)

P2-T2 copies these bullets into `docs/android/DECISIONS.md` under "Decided while the user was away (review)", after PD50, preceded by the line `- **P2 planner (2026-10-08):** decisions for the FFI facade, cards in docs/android/phases/P2.md.` with each PD as a sub-bullet.

- **PD51 Card layout.** Twelve cards in five waves: core, gate tools and parity tools (wave 1); common records and events, helpers, Gradle JVM build (wave 2); five domain facades in waves 3 and 4 (3 then 2, to bound RAM); JVM end-to-end tests, apiCheck and FFI.md (wave 5). The core card pre-creates every later file as a stub and declares every dependency, so the parallel cards never edit the same file, `Cargo.toml` or `Cargo.lock`.
- **PD52 Parity target and extras.** `pos-ffi` depends on `pos-engine` with `default-features = false, features = ["cert"]` (HubRise in, peppol out). Parity target 84/84 (86 wrappers minus the peppol `sign_invoice_fiscal`, `issue_b2b_invoice`): each cert command has its wrapper, its engine function and an async method of the same name on `PosEngine` with the same parameter names, calling the same engine function, through `self.blocking` when the engine function is sync and `self.spawn` when it is async. Extras outside parity: `PosEngine.open` (the only synchronous export, a constructor Kotlin calls on Dispatchers.IO), `shutdown`, `events`, `EventStream.next`, and the free functions `init_logging`, `pos_sw_version`, `install_init_db`, `check_config_bundle`, `qr_matrix`, `verify_minisign`, `verify_bundle`, `settle_preview`, `cash_due_cents`, `vat_split`. The lifecycle method is `shutdown`, not `close`, because UniFFI Kotlin objects already implement `AutoCloseable.close()`.
- **PD53 Engine options.** `EngineOptions { data_dir, config_bundle, device_id: Option, timers: Option<EngineTimersMs> }`. `data_dir` and `config_bundle` must be absolute (settles PD27c); the configuration is always `ConfigSource::Bundle` (no `File`, no `DevelopmentDefaults` over the FFI: no silent TEST identity). The identity is built in Rust, never passed by Kotlin: `pili-pos-android/` plus the `pos-ffi` crate version, which is `1.0.0-dev` during development (DECISIONS section 2). `http_tls` is always `HttpTls::RootsOnly` with the roots of `webpki-root-certs` 1.0.9 (B1c). `support_program` is `None`. Timers default to `EngineTimers::default()` except `printer_status_read` 2 s (PD37); a timer of 0 or less is refused.
- **PD54 Errors.** `PosError` (Kotlin `PosException`): `Coded { code, params: map }`, `Fdm { detail }`, `Internal { detail }`, `EngineClosed`. Fields are named `detail`, never `message` (it would clash with `Throwable.message`). Mapping follows `describeError` of the Vue UI: a string starting with `FDM` is `Fdm` (raw text, translated later like `fdmMessages.ts`); `code|k=v|...` whose code is in `errors::ALL` or `errors::hubrise::ALL` (85 codes at `042d911`) is `Coded`; anything else, and every record conversion failure (`contract: ...`), is `Internal`. A panic, in the future body or in a spawned task (re-raised with `std::panic::resume_unwind`), reaches Kotlin as UniFFI's `InternalException`, the single Fatal channel. A task cancelled by the runtime shutting down is `EngineClosed`. No new engine error code.
- **PD55 Calls and lifecycle.** Every export except `open` is `async`. Sync engine functions run in `spawn_blocking`, async ones in `spawn`, both on the engine's own multi-thread runtime (4 workers, thread name `pos-engine`) and awaited through the JoinHandle, so a cancelled coroutine detaches and never aborts a sign in flight. Each call holds an `Arc<Engine>`. `shutdown()` refuses new calls (`EngineClosed`), cancels the shutdown token, awaits the background tasks and the in-flight calls (strong count back to 1) for at most 30 s, then drops the engine, which releases `engine.lock` (settles PD27a); on timeout it returns `Internal` and keeps the engine. The runtime sits in an `Option` and is dropped with `shutdown_background()`. `open` runs `Engine::open` then `start_background` on the runtime.
- **PD56 Records.** FFI records and enums mirror the engine types with the same serde attributes, derive `Serialize`, `Deserialize` and `uniffi::Record`/`uniffi::Enum`, carry `#[serde(deny_unknown_fields)]` (except a type marked `// contract: custom` with its own conversion and test), and are converted through `serde_json` (`convert::out` engine to FFI, `convert::inp` FFI to engine). Unsigned integers become `i64`, chrono times `String`, `serde_json::Value` a JSON text `String` (`convert::json_text`), `Vec<u8>` stays bytes. The euro `f64` amounts of `FiscalTicket` stay `f64` (display only, the engine and Vue contract). `check_fdm_status` and `list_fiscal_events` get typed records built from their JSON shape. Each record has a contract test against the testkit (`json(engine value) == json(FFI value)` for outputs, field-by-field for inputs).
- **PD57 Events.** `PosEngine.events()` subscribes an `EventStream` to a `tokio::sync::broadcast` channel (capacity 256) fed by the engine's `EventSink`. `PosEvent` has one variant per engine topic (`fdm-sign-messages`, `fdm-status`, `session-locked`, `presence-failed`, `webshop-order-received`, `webshop-order-updated`, `catalog-updated`, `catalog-rejected`, `catalog-awaiting-adoption`) plus `Resync { missed }` when a reader lags. `next()` returns `null` after `shutdown`. A payload that fails conversion is logged and replaced by `Resync { missed: 1 }`.
- **PD58 Logging.** `init_logging(log_dir, filter)` installs a `tracing-subscriber` 0.3.23 subscriber with a daily `tracing-appender` 0.2.5 file (`pili-pos.log.<date>` in the app-private directory Kotlin passes, 90 files kept) and, on Android, logcat through `__android_log_write` of liblog declared in `pos-ffi` itself (no new crate). That file, `src/logging.rs`, holds the only `cfg(target_os = "android")` and the only globals of `pos-ffi` (the subscriber and the appender guard, `OnceLock`). A panic hook logs every panic to both sinks before the previous hook. The engine still has no global.
- **PD59 Workspace and lock.** `android/rust` is its own workspace (members `pos-ffi`, `uniffi-bindgen`), never a member of the root one (`exclude = ["android"]` already). Its `Cargo.lock` is seeded with a copy of the root `Cargo.lock` so shared crates keep the root versions; target dir `<repo>/target/android-rust` through `android/rust/.cargo/config.toml`; `[profile.dev] debug = "line-tables-only"` to save disk; `[profile.android-release]` as S2. New crates, exactly pinned: `uniffi`/`uniffi-bindgen` `=0.32.2`, `minisign-verify` (latest 0.2.x, pinned by P2-T1), dev-only `minisign` (signing in tests, so no secret key is committed). Lock parity rule (`check_lock_parity.sh`): the set of (name, version) in `cargo tree -p pos-engine -e normal,build --target all` is identical in both workspaces (root with `--no-default-features --features cert`); a difference is allowed only with a reason line in `scripts/android/lock_parity_allow.txt` (empty at the start).
- **PD60 Kotlin side in P2.** A minimal Gradle build in `android/` (wrapper 8.11.1 with the pinned sha256, Kotlin 2.2.20, JDK 17 toolchain, pins copied from moyun-handheld). In P2 `:pos-core` is a Kotlin/JVM library whose main sources are the UniFFI bindings generated in library mode from the host debug dylib with `android/rust/jvm-uniffi.toml` (package `uniffi.pos_ffi`, never committed); tests use the plain JNA 5.19.1 jar. P3.1 turns `:pos-core` into an Android library (android-flavour bindings from the cargo-ndk `.so`, `android-uniffi.toml`) and keeps these tests as host unit tests. `apiCheck` (Kotlin binary-compatibility-validator, version pinned by P2-T12) snapshots `android/pos-core/api/pos-core.api`, written once in P2-T12. The checksum mismatch test uses a dylib built with the `pos-ffi` feature `abi-mismatch` in `target/android-rust-mismatch`, in a separate Gradle task `mismatchTest` wired into `check`.
- **PD61 Bundle format.** For P4.4: a bundle directory holds `MANIFEST.json` (`{"format":1,"files":[{"path","size","sha256"}]}`) and `MANIFEST.json.minisig` (minisign over the manifest bytes). `verify_bundle(dir, public_key)` checks the signature, then every listed file (relative path, no `..`, no absolute path, no symlink, size and SHA-256 equal), and refuses any unlisted regular file other than the two manifest files. Verification failures are not exceptions: `BundleCheck`/`MinisignCheck` carry `valid` and a `problem` string in the `code|k=v` form with codes `bundle_signature_invalid`, `bundle_manifest_invalid`, `bundle_path_invalid`, `bundle_file_missing`, `bundle_size_mismatch`, `bundle_hash_mismatch`, `bundle_unlisted_file`, `minisign_key_invalid`, `minisign_signature_invalid` (texts come with P4.3). The public key is a parameter; P4.4 and P6 compile theirs in. File work runs on a dedicated thread, never on the caller's.
- **PD62 Money helpers.** `settle_preview` and `cash_due_cents` call `pos_fiscal::payment::settle` (the checkout's function) and map its errors to the codes the checkout uses (`payment_invalid`, `payment_exceeds_total`, `payment_incomplete`). `vat_split` reproduces `ui/src/components/VatSummary.vue` exactly (per-code sum of unit price times quantity, codes A B C D in that order, X omitted, `vat = total - Math.round(total * 10000 / (10000 + rate * 100))` with JavaScript rounding); it can differ by one cent from an integer truncation (the former `pos_core::vat::VatCode::vat_from_inclusive`, since removed), recorded and not changed: display only, the ticket VAT comes from the FDM. Kotlin never multiplies or rounds money.
- **PD63 Provisional freeze (PD48 applied).** Every card gate and the phase gate run `scripts/android/check_linux_frozen.sh --ref 042d91135940cb3f678a3f5e2947744a9d05ce4d` (added by P2-T2; the default tag mode keeps printing SKIP until a `linux-*` tag exists). P2 changes only `android/`, `scripts/android/`, `docs/android/` (never `docs/android/baseline/`); anything else is an escalation.
- **PD64 Gate cost.** Card gates build on the host only. The arm64 `android-release` build with the 16 KB alignment and android-flavour bindgen check (`--android`), the root test inventory (`--root`) and the strict 84/84 parity, `:pos-core:check` and `ffi-doc` (`--exit`) run in the integrator's phase gate. Workers warm-start from `int/target/android-rust` (APFS clone), never from the whole `int/target`.
- **PD65 Mocks for JVM tests.** `pos-fdm-mock` and `pos-printer-mock` are built from the root workspace with `cargo build --locked --manifest-path <repo>/Cargo.toml --target-dir <repo>/target/android-mocks` (root `Cargo.lock` unchanged) and started by the tests as processes on free ports (`PORT`, `HTTP_PORT`). Rust tests serve them in-process (`pos_fdm_mock::app()`, `pos_printer_mock::bind`).
- **PD66 Exit without the user.** P2 sets no freeze tag and runs no `check_repro.sh` (PD47 still open). With the user away the planner writes `P2-exit.md` and the chain may continue to P3 on `android/int`; merging into main waits for the user.
