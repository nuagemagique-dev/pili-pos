### 2.3 Lock Task features reset at every boot (trap)

`setLockTaskFeatures(NONE)` is not kept across a reboot: the value reads 16 (GLOBAL_ACTIONS) after every
boot, although 0 was applied before. After a reboot a long press on the power key shows the power menu
inside Lock Task, and calling `setLockTaskFeatures(NONE)` again hides it (read back 0). Evidence:
`spikes/s4/evidence/S4-T6/features-trace.txt` (`after-safeboot-setprop features=16`),
`power-menu-after-boot.txt`, `power-menu-reapplied.txt`, `kiosk_features-none.json`.

**Evidence.** `spikes/s4/evidence/S4-T1/` (`g_crash_*`, `g_second_crash.png`,
`g_crash_with_stock_launcher_task_*`, `g_reboot_logcat.txt`, `f_power_*.png`),
`spikes/s4/evidence/S4-T6/boot-lifecycle-tail.txt`.

**Consequences.**
- Recovery relies on the app being the HOME activity (persistent preferred activity, MAIN + HOME +
  DEFAULT) plus the relock in `onResume` from the persisted flag.
- P4.5 calls `setLockTaskFeatures(NONE)` at every start, before `startLockTask()`.
- P6 sets `no_system_error_dialogs` (otherwise the second crash of a boot freezes the till).
- The stock launcher task is a recovery hazard: reboot after `kiosk_setup`, or force-stop or hide the
  stock launcher, or rely on the `MY_PACKAGE_REPLACED` and watchdog paths. How the Sunmi launcher behaves
  is hardware residue.
- The app's own exit path (`lock_off`) is the only way out for a technician: `am force-stop` is refused
  for the owner package.

**Reading.**
- `Build.getSerial()` as device owner returns exactly what `adb shell getprop ro.serialno` shows. It was
  measured with READ_PHONE_STATE granted (the grant is part of `kiosk_setup`); it was not tested without
  the grant (`spikes/s4/notes/S4-T1.md`, P4 findings).
- The app process cannot read `ro.serialno` or `ro.boot.serialno` by any route tried, so the
  "`ro.serialno` fallback" of DECISIONS section 3 does not exist inside the app.
- `getWifiMacAddress(admin)` works as device owner but returns `null` while Wi-Fi is off. This AVD has a
  fixed fake MAC, so nothing can be said about MAC randomisation or reset.

**Outcome of the deviceId rule (decided by the S4 planner while the user was away).**
Case (1) applies: `Build.getSerial()` works for the device owner on API 33 and is stable across reboot
(also with Wi-Fi off). The hardware serial stays the deviceId (Q4 stands). `getWifiMacAddress` is
evaluated and not chosen, for these measured reasons: it returns `null` with Wi-Fi off (a till installed
on Ethernet, or one whose radio is off, depends on a radio state the installer does not control), its
value on this AVD is a fixed fake (`02:15:b2:00:00:00`), and Q505 b) of the producer FAQ already accepts
a hardware serial. Cases (2) and (3) do not apply. The real Sunmi serial format, and whether the D3 Pro
firmware returns it to the device owner, stay hardware residue.

**Consequences (P4.4).** Read `Build.getSerial()` once at provisioning, with READ_PHONE_STATE granted by
the owner through `setPermissionGrantState`; fail provisioning on any exception; no in-app fallback, no
`ANDROID_ID`, no generated value. Store it, compare it at every `Engine::open` (DECISIONS section 3).

## 4. SAF export to a removable volume

**Method.** `spikes/s4/run_t4.sh` (about 6 minutes with the build). The export stages 200 `heartbeat`
rows, a `backupTo` copy, a 20 MiB `data.bin` and a log in `cacheDir`, hashes them with
`ProbeEngine.sha256File`, then writes a directory `pili-export-<timestamp>` and 4 files through a
persisted tree URI (`DocumentsContract.createDocument`, `openFileDescriptor("w")`, `fd.sync()`), the
manifest last. Cases: A (picker, Lock Task off), B (picker in Lock Task, only our package allowed),
C (DocumentsUI allowlisted), D (export in Lock Task, no picker), E (unmount, remount, reboot).
Evidence: `spikes/s4/evidence/S4-T4/` (`run.log`, `items.tsv`, `facts.txt`, `sha256sum-device-*.txt`,
`shasum-host-*.txt`, `picker-*.txt`, 7 PNGs).

**Deviation (stand-in volume).** The AVD's own 2 GB SD card does not attach: with `-sdcard <image>` the
guest fails first-stage mount (`Failed to mount required partitions early`, `InitFatalReboot: signal 6`)
and boot-loops with adb `offline` (`spikes/s4/evidence/S4-T4/avd_sdcard_attempt.txt`). The stand-in is
vold's virtual SD disk (`sm set-virtual-disk true`, `sm partition <disk> public`): a removable public
vfat volume, `Virtual SD card`, uuid `BFD1-0A11`, 512 MiB, served by the same
`com.android.externalstorage.documents` provider and DocumentsUI as a USB stick. It is a file on the host
disk, so there is no USB bus and the throughput is protocol overhead only.

**Consequences (P6).**
- The manager picks the folder once per stick, from a PIN-gated screen with no open order. Before the
  picker, check `StorageManager.storageVolumes` for `isRemovable && !isPrimary && state == "mounted"`;
  if there is none, show "Insert the USB stick" and do not open the picker.
- Use `StorageVolume.createOpenDocumentTreeIntent()` through `registerForActivityResult` (registered as a
  field), started from the Lock Task activity itself, never with `FLAG_ACTIVITY_NEW_TASK`; then
  `takePersistableUriPermission(READ|WRITE)` and store the URI.
- DocumentsUI stays off the Lock Task allowlist (case B works with only the app allowed).
- The root cannot be granted: tell the manager to create a sub-folder (suggested name `PILI-EXPORT`),

  product name.
- Export without a picker uses the persisted URI; the manifest is written last, so a missing or short
  manifest tells the SPF the export is incomplete. Nothing is deleted on error.
- A missing stick shows "stick not found (volume <uuid> not mounted)" from the pre-check; a different
  stick (new UUID) needs "Change folder", which releases the old grant.
- Hashes are computed on the staged copy in `cacheDir`, which needs free space of the largest file.
- No storage permission is needed beyond the tree grant.

removed, the system starts HOME three times and a new process starts. In one development run the first
HOME start failed with `SecurityException: Package ... is currently frozen!` and the system retried. Lock

- The OS is a second line behind the app for downgrade and for another key, **not** for a same-versionCode

- `DISALLOW_INSTALL_UNKNOWN_SOURCES` and `_GLOBALLY` do not block the owner's session (U2) and do not

- Do not declare `REQUEST_INSTALL_PACKAGES` in the production manifest. Production pulls over HTTPS from
  GHCR: the cleartext rule for `10.0.2.2` of the spike is not carried over.
- Not tried: hiding the stock launcher and Settings through `setApplicationHidden` or
  `setPackagesSuspended` so that nothing but our app can show during the gap; a different package name
  inside a session created with `setAppPackageName`.

  the first `onResume`, service foreground about 1.2 s later. Keep this path; treat the boot receiver as
  optional.

## 10. Power cut

**Method.** `spikes/s4/run_t7.sh`, after the soak: last logged beat read from logcat, then `adb emu kill`
(no clean shutdown, no `svc power shutdown`), wait for the qemu process to exit, `emu.sh up`. Evidence:
`spikes/s4/evidence/S4-T7/` (`power-cut-kill.txt`, `power-lifecycle.txt`, `power-service-record.txt`,
`power-db-check.json`, `power-after.png`).

| Item | Observed | Verdict |
|------|----------|---------|
| Cut | last logged beat n=184 (pid 2966), emulator back with `sys.boot_completed=1` | INFO |
| Seconds to LOCKED | **3 s** after `sys.boot_completed=1` (HOME activity created at 16.7 s uptime, `onResume` relocks) | PASS |
| Service and beats | first beat 5 s after boot_completed (`n=185 pid=1635`), `service_running=true`, variant typed, `isForeground=true` | PASS |
| Integrity | `ok` | PASS |
| Heartbeat rows | 185 against last logged 184 (`synchronous=FULL`: the committed row survived, nothing lost) | PASS |
| Network after the cut | `nc -w 2 10.0.2.2 9100` rc 0, `airplane_mode_on=0`; the service printed once at restart | INFO |

**Limit.** `adb emu kill` ends the qemu process without a guest shutdown: the guest page cache and the
unflushed settings and policy files are lost, the host keeps what the guest already wrote to the virtual
disk. It does not model a real flash device losing its write cache.

**Consequences.** Recovery after a power cut needs no human action on the emulator. The real plug pull,
the boot time from power on to LOCKED (the emulator's 17 s uptime to HOME is not representative) and the
owner record staying consistent after an abrupt cut (see section 1) are P7 items on the D3 Pro.
Two related traps from S4-T7: the AVD can come up with airplane mode on after an abrupt stop (every print
failed with `os error 101`; `run_t7.sh` now checks `settings get global airplane_mode_on`), so a print
failure with os error 101 is a network state problem, not an engine one; and a shell-started activity
does not wake a sleeping screen (the script sends `KEYCODE_WAKEUP` first).

## 11. bcrypt timing

**Method.** `cmd bcrypt --es cost 12 --es runs 3` in the app (Rust engine, off the main thread) and
`cargo run --release --example bcrypt_host` on the host (`spikes/s4/rust/s4-probe/examples/bcrypt_host.rs`).
Evidence: `spikes/s4/evidence/S4-T3/run.log` (`bcrypt.emulator`, `bcrypt.host`).

| Where | Runs at cost 12 | Median |
|-------|-----------------|--------|
| Emulator on the M1 host (arm64 guest, not a Qualcomm core) | 306, 295, 291 ms | **295 ms** |
| Host M1, native | 232, 232, 232 ms | **232 ms** |

Across four earlier local runs the emulator median was between 291 and 302 ms (terminal log, not kept as
files). A PIN check is well under a second on this class of CPU. The Qualcomm timing is hardware residue.

## Recommendations for the later phases

**P4.1 (app skeleton)**
- Wire the Rust build as the spike does: a Gradle Exec task runs `cargo ndk` and library-mode bindgen
  with `~/.cargo/bin` first on PATH. `cargo ndk -o` copies the unstripped `.so` (30,876,712 B); AGP strips
  the packaged copy (about 2.2 MB stripped, 3.6 MB with `--strip-debug`). Bindgen reads the unstripped
  file.
- Call `uniffiEnsureInitialized()` then open the engine once, off the main thread (34 ms here).
- Manifest: `minSdk` 33 and `targetSdk` 36 work; no `REQUEST_INSTALL_PACKAGES`, no storage permissions,
  no cleartext rule; the app label is the product name (it appears in the SAF Allow dialog).

**P4.2 (EngineHolder, foreground service)**
- Start the service with the typed call `ServiceCompat.startForeground(..., FOREGROUND_SERVICE_TYPE_SPECIAL_USE)`
  inside a try/catch with the plain `startForeground(id, notification)` as the fallback.
- Manifest: `foregroundServiceType="specialUse"` with the `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` property, the
  permissions `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`, `POST_NOTIFICATIONS` (granted by the
  owner with `setPermissionGrantState`) and `RECEIVE_BOOT_COMPLETED` only if the boot receiver is kept.
- Start it from `onResume` after the Lock Task relock; `START_STICKY`; treat the boot receiver as
  optional (not proven). Keep every engine call off the main thread. Do not rely on a wake lock until the
  real soak says otherwise.
- The engine must make a killed state recoverable (the app is force-stopped by an update and by a crash).

**P4.4 (provisioning, deviceId)**
- Document the adb path: no account, one user, `adb install`, `dpm set-device-owner`, read the text and
  `dpm list-owners`, retry after a transient `being removed` error, never trust the exit code.
- deviceId: `Build.getSerial()` as owner with READ_PHONE_STATE granted, read once, stored, compared at
  every open; fail provisioning if it throws; no `ro.serialno` fallback inside the app, no `ANDROID_ID`.
- Order: device owner, kiosk setup, signed bundle, tests, then `DISALLOW_DEBUGGING_FEATURES`. End with a
  flush (`sync`, a wait of about 12 s, or a reboot) before reporting success; treat "owner but
  `SecurityException`" as recoverable.

**P4.5 (navigation shell, Lock Task entry)**
- `setLockTaskPackages([self])`, persistent preferred activity MAIN + HOME + DEFAULT to `MainActivity`,
  the kiosk flag in SharedPreferences, relock in `onResume`.
- `setLockTaskFeatures(NONE)` at every start, before `startLockTask()` (it reads 16 after every boot).
- `no_system_error_dialogs`; a plan for the stock launcher task (reboot after setup, force-stop or hide
  it, the `MY_PACKAGE_REPLACED` receiver); a manager-PIN exit path (`lock_off`).
- Start the SAF picker from the locked activity without `FLAG_ACTIVITY_NEW_TASK`; DocumentsUI stays off
  the allowlist.

**P5 (UI)**
- dp scale: 1 dp = 1 CSS px, with the `LocalDensity` wrapper `Density(widthPx / 1920f, 1f)` and `fontScale`
  1.0. Immersive on every screen, re-applied on resume.
- Fonts: bundle Noto Sans SC Regular and Bold (subset), system font as fallback. Tag Chinese runs
  `zh-Hans` and French `fr` per `Text`.
- Export screen: volume pre-check result, the 4 picker steps and the folder name to type, progress per
  file, the exception text for a missing stick, result code 0 handled as cancelled. Printer state shows
  "unknown" when the DLE EOT answer is missing. After an update, a "version updated" confirmation built
  from the receiver data (there is no installer dialog).

**P6 (compliance and hardening)**
- Restriction set: the 12 restrictions of 8.1 plus `no_system_error_dialogs`, `setUninstallBlocked`,
  `setAutoTimeEnabled(true)`, `setAutoTimeZoneEnabled(false)`, `setTimeZone("Europe/Brussels")`,
  `STAY_ON_WHILE_PLUGGED_IN=7`, keyguard and status bar disabled, postpone update policy,
  `DISALLOW_DEBUGGING_FEATURES` last. Stays off: `DISALLOW_MOUNT_PHYSICAL_MEDIA` (the export needs the
  volume) and `DISALLOW_CONFIG_WIFI` (open, see Q16: left off, with a manager-PIN Wi-Fi screen in the app).
- SAF flow: as in section 4 (pre-check, picker from the locked activity, sub-folder, persisted grant,
  manifest last, nothing deleted on error, hashes on the staged copy).
- Updater: prechecks in the order of section 7, SHA-256 and SHA-1 and minisign in the engine,
  versionCode strictly greater checked by the app (the OS accepts a same-versionCode reinstall), signer
  equal, DB backup and marker before `commit`, `STATUS_PENDING_USER_ACTION` is an error, install status
  and audit "done" row in the new process, `MY_PACKAGE_REPLACED` receiver kept, no
  `REQUEST_INSTALL_PACKAGES`, HTTPS only.
- Printing: DLE EOT as best effort with a separate status step and a longer timeout; the customer ticket
  is French only unless a raster path is built for Chinese.

**P7 (runbook)**
- Run `SOAK_MINUTES=1440 caffeinate -i spikes/s4/run_t7.sh` adapted to the D3 Pro (adb serial in place of
  `emu.sh`), with the screen-off, Doze and trim events kept and a real plug pull in place of
  `adb emu kill`.
- Record on the unit: `wm size`, `wm density`, serial, MAC behaviour, bcrypt time, printer status timing
  on the shop LAN, boot time to LOCKED, BOOT_COMPLETED, the recovery key combination, the vendor launcher
  and the SUNMI extension, USB sticks (FAT32 and exFAT).
- Emulator hazards for the e2e scripts: flush 12 s (`sync; sleep 12; sync`) before stopping the AVD after
  a package or owner change; check `airplane_mode_on`; send `KEYCODE_WAKEUP` first; wait for
  `init.svc.bootanim=stopped` before a screenshot; `uiautomator dump` plus `spikes/s4/tools/ui.py` is a
  template for picker e2e; the virtual SD (`sm set-virtual-disk true`, `sm partition <disk> public`,
  `sm unmount|mount <volume id>`) is a repeatable stick for any AVD.

## How to rerun

Prerequisites: the AVD `sunmi_d3_pro_api33` (one emulator at a time: `spikes/s4/emu.sh up` reuses a
running one and only stops one it started, `emu.sh down`), `ANDROID_HOME`, NDK 27.1.12297006 (default
path in `spikes/s4/lib.sh`), JDK 17, rustup cargo first on PATH (Homebrew cargo has no Android std),
cargo-ndk 4.1.2, Python 3 (scripts use `python3 -I`), `sqlite3` from platform-tools (S4-T4), the root
crate `pos-printer-mock` (built by `run_t3.sh` and `run_t7.sh` unless `S4_SKIP_BUILD=1`). Keep the host
free of other heavy builds: S4-T7 swapped heavily on a 16 GB Mac.

| Script | Content | Time | Notes |
|--------|---------|------|-------|
| `spikes/s4/run_t1.sh` | device owner, Lock Task, deviceId | a few minutes | starts and stops the emulator |
| `cd spikes/s4/rust && cargo test` and `./build_android.sh <jni dir> <kotlin dir>` | S4-T2 probe library, host tests, Android build | cold about 2 m 10 s | no emulator |
| `spikes/s4/run_t3.sh` | printing, display, CJK, bcrypt | about 5 minutes with the builds | needs the printer mock |
| `spikes/s4/run_t4.sh` | SAF export | about 6 minutes with the build | creates the virtual SD disk |
| `spikes/s4/run_t5.sh` | silent update | about 12 minutes with the builds | `S4_HTTP_PORT` (8765), `spikes/s4/build_variants.sh` |
| `spikes/s4/run_t6.sh` | restrictions, boot, adb off | about 6 minutes plus 2 minutes of adb offline | `S4_ADBOFF_SECONDS` (120) |
| `caffeinate -i spikes/s4/run_t7.sh` | soak, power cut, teardown | about 40 minutes | `SOAK_MINUTES` (30; 1440 for 24 h), `S4_SKIP_POWERCUT=1` |

Common environment: `S4_EVIDENCE_DIR=<dir>` writes the evidence elsewhere (reviewers use
`$WT/target/s4/review/S4-T<n>`), `S4_SKIP_BUILD=1` skips the builds, `S4_AVD` picks another AVD. The
reviewer rerun of S4-T7 is `SOAK_MINUTES=5 S4_EVIDENCE_DIR=$WT/target/s4/review/S4-T7 spikes/s4/run_t7.sh`
(events scale with the soak length). Each script prints one `ITEM | VERDICT | detail` line per item and
ends with the count of must-PASS failures.
